1
Why Option B (computeIfAbsent) is ideal

computeIfAbsent computes the new value lazily. The mapping function is only executed once the lock on the target bucket bin is established and confirms the key is still missing. This eliminates race conditions, prevents redundant object allocations, and avoids double-locking synchronization overhead.

2
Why Option A (putIfAbsent) falls short

With putIfAbsent(K, V), the prospective value object must already be instantiated before calling the method. If creating V is resource-heavy (e.g., opening a database connection or computing expensive cryptographic hashes), that effort is completely wasted if another concurrent thread inserted the key first.
